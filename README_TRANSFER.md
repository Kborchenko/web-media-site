# Передача сайта CODE TECH новому владельцу

## 1. Что находится в архиве

Это автономная копия статического корпоративного сайта CODE TECH без Git-истории и без привязки к исходному GitHub-репозиторию. В корне находятся HTML, CSS, JavaScript, локальные шрифты и изображения. Каталог `assets/` содержит изображения секций сайта.

В копию специально не включены `.git`, кэши, временные файлы, скриншоты аудита, рабочие материалы и результаты предыдущих проверок. Все 34 файла последней зафиксированной версии сайта включены; изображения, отсутствовавшие в рабочем каталоге исходного проекта, восстановлены из последнего локального Git-коммита.

## 2. Технологии и структура

- Статический HTML5: `index.html`.
- CSS без препроцессора: `styles.css`.
- JavaScript без фреймворка и сборщика: `main.js`, `rings.js`, `matrix-text.js`, `bento.js`, `bento-pointer.js`, `company-bento.js`.
- Анимации GSAP 3.12.5 и ScrollTrigger загружаются по HTTPS с CDNJS.
- Локальные шрифты Onest и Luna Obscura в формате WOFF2.
- Локальные изображения WebP в корне и в `assets/`.
- `.nojekyll` отключает обработку Jekyll на GitHub Pages.

В проекте нет `package.json`, lock-файла, npm-зависимостей, серверной части, базы данных, переменных окружения и обязательного этапа сборки.

## 3. Перед первой публикацией

Выполните поиск по проекту и замените следующие заглушки и сведения:

1. `owner@example.com` в `index.html` — на действующую почту нового владельца. Адрес используется в контактах, политике конфиденциальности и согласии на обработку персональных данных.
2. Сведения об операторе персональных данных и город в юридических текстах — на актуальные данные владельца. Рекомендуется юридическая проверка документов перед приёмом реальных заявок.
3. Строки `FORM_ENDPOINT` и `PROJECT_FORM_ENDPOINT` в начале `main.js` — на HTTPS-адреса обработчиков форм. Пока они пустые, формы работают в демонстрационном режиме и ничего не отправляют.
4. Контакт Telegram в `index.html`: сейчас показано «будет добавлен».

Секреты нельзя помещать в HTML или JavaScript: всё содержимое GitHub Pages доступно посетителям. Если обработчику форм нужен секретный ключ, храните его только на стороне отдельного сервера или serverless-функции.

## 4. Локальный запуск

Установка зависимостей не требуется. Не рекомендуется открывать `index.html` напрямую через `file://`; запустите локальный HTTP-сервер из корня проекта.

Вариант с Python:

```powershell
py -m http.server 8000
```

Если команда `py` недоступна:

```powershell
python -m http.server 8000
```

Откройте `http://localhost:8000/`. Для остановки сервера нажмите `Ctrl+C`.

Для полной анимации нужен доступ к `https://cdnjs.cloudflare.com`, откуда загружаются GSAP и ScrollTrigger. Без CDN основное содержимое и стили остаются доступными, но часть анимаций отключится.

## 5. Production-сборка

Отдельной production-сборки нет: содержимое этой папки уже является готовым сайтом. Публиковать нужно все файлы и каталоги из корня без изменения структуры. Критически важно сохранить файл `.nojekyll`.

Быстрая локальная проверка перед публикацией:

```powershell
py -m http.server 8000
```

Затем проверьте главную страницу, навигацию, изображения, мобильную версию, обе формы и юридические окна.

## 6. Новый GitHub-репозиторий

1. В аккаунте нового владельца создайте пустой репозиторий на GitHub. Не добавляйте при создании README, `.gitignore` или лицензию, чтобы избежать лишнего конфликта первого push.
2. В терминале откройте распакованную папку и выполните:

```powershell
git init
git add .
git commit -m "Initial site transfer"
git branch -M main
git remote add origin https://github.com/NEW_OWNER/NEW_REPOSITORY.git
git push -u origin main
```

Замените `NEW_OWNER` и `NEW_REPOSITORY`. Архив не содержит старого remote, истории или учётных данных.

## 7. GitHub Pages

Для этого проекта GitHub Actions не нужен.

1. Откройте репозиторий на GitHub.
2. Перейдите в **Settings → Pages**.
3. В **Build and deployment → Source** выберите **Deploy from a branch**.
4. Выберите ветку `main` и каталог `/(root)`, затем нажмите **Save**.
5. Дождитесь публикации и проверьте адрес вида `https://NEW_OWNER.github.io/NEW_REPOSITORY/`.

Все пути к локальным ресурсам относительные, поэтому сайт поддерживает публикацию как в корне пользовательского домена, так и в подпапке репозитория GitHub Pages.

Официальная инструкция: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## 8. Собственный домен

Сначала добавьте домен в настройках GitHub, затем меняйте DNS. Это снижает риск перехвата домена.

1. По возможности подтвердите домен в **GitHub account Settings → Pages → Add a domain** и сохраните выданную TXT-запись в DNS.
2. В репозитории откройте **Settings → Pages**.
3. В поле **Custom domain** укажите домен, например `www.example.com`, и сохраните. При публикации из ветки GitHub добавит или обновит файл `CNAME` в корне репозитория.
4. У регистратора домена настройте DNS:
   - для `www` или другого поддомена создайте `CNAME`, направленный на `NEW_OWNER.github.io` без имени репозитория;
   - для корневого домена создайте четыре `A`-записи: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`;
   - при необходимости добавьте рекомендованные GitHub `AAAA`-записи из актуальной документации;
   - не используйте wildcard-запись `*` для GitHub Pages.
5. Удалите конфликтующие старые `A`, `AAAA`, `ALIAS`, `ANAME` или `CNAME` записи для того же имени.
6. Дождитесь распространения DNS; это может занять до 24 часов.

Проверка DNS в PowerShell:

```powershell
Resolve-DnsName example.com
Resolve-DnsName www.example.com
```

Официальные инструкции:

- https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site
- https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/verifying-your-custom-domain-for-github-pages

## 9. Бесплатный HTTPS

GitHub Pages выпускает сертификат автоматически после корректной настройки домена и DNS.

1. Дождитесь успешной DNS-проверки и выпуска сертификата в **Settings → Pages**.
2. Включите **Enforce HTTPS**.
3. Проверьте, что сайт открывается по `https://` и нет предупреждений о mixed content.

В текущем проекте внешний JavaScript загружается по HTTPS, а локальные ресурсы используют относительные пути. Официальная инструкция: https://docs.github.com/en/pages/getting-started-with-github-pages/securing-your-github-pages-site-with-https

## 10. Работа через Codex или Claude Code

1. Распакуйте архив в отдельную папку.
2. Откройте эту папку как рабочий проект.
3. Перед изменениями попросите агента прочитать `README_TRANSFER.md`, `README.md`, `index.html`, `styles.css` и связанные JS-файлы.
4. Запускайте локальный HTTP-сервер и проверяйте результат в браузере после каждого заметного изменения.
5. Храните изменения в новом Git-репозитории небольшими коммитами.
6. Не добавляйте токены, пароли или закрытые ключи в репозиторий. Используйте серверную конфигурацию внешнего обработчика форм.

Примеры задач для агента:

- «Замени контактную почту и сведения владельца во всех юридических текстах, не меняя дизайн».
- «Подключи оба обработчика форм к указанному HTTPS endpoint и добавь обработку ошибок».
- «Проверь все локальные пути и адаптивность сайта перед публикацией».

## 11. Внешние сервисы и ограничения

- **CDNJS**: GSAP 3.12.5 и ScrollTrigger загружаются без учётной записи. Для полностью офлайн-версии новый владелец может скачать разрешённые лицензией файлы библиотек, хранить их локально и заменить два CDN URL в `index.html`.
- **Обработчики форм**: не подключены; новый владелец должен предоставить собственные endpoint-ы и проверить CORS, хранение данных, уведомления и требования законодательства.
- **Почта и Telegram**: должны быть заменены/добавлены новым владельцем.
- **GitHub Pages, GitHub-аккаунт, домен и DNS**: создаются и настраиваются новым владельцем самостоятельно.
- **Шрифты и изображения**: находятся локально в проекте. Перед коммерческой публикацией новый владелец должен убедиться, что права на бренд, тексты, шрифты и изображения переданы ему отдельно; наличие файлов в архиве само по себе не заменяет передачу прав.

## 12. Что было обезличено

- Исключена директория `.git`, поэтому старые GitHub remote, имя репозитория и история не передаются.
- Файл `CNAME` отсутствует: копия не привязана к прежнему домену.
- Контактный адрес на прежнем домене заменён на зарезервированную заглушку `owner@example.com`.
- Переменные окружения и секреты не требуются; действующих токенов, ключей, паролей и закрытых сертификатов в передаваемой структуре не обнаружено.

После замены заглушек и подключения внешних сервисов проект можно обслуживать независимо от аккаунтов прежнего владельца.
